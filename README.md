### 01 / THE PRACTICE

I build products as **worlds**, not pages.

A project starts with a behavior, a mood, a system, or a constraint — then turns into an interface, a workflow, a desktop surface, or a full product architecture. I care about the gap between *working* and *feeling finished*.

<table>
<tr>
<td width="33%" valign="top">

**INTERACTION**  
Motion, scene logic, transitions, responsive behavior, tactile detail.

</td>
<td width="33%" valign="top">

**SYSTEMS**  
APIs, authentication, role models, state, data, multi-tenant architecture.

</td>
<td width="33%" valign="top">

**PRODUCT**  
Flows, hierarchy, constraints, usability, shipping, iteration.

</td>
</tr>
